SOQL & SOSL

SOQL (Salesforce Object Query Language) reads records from one object and its relationships. SOSL (Salesforce Object Search Language) runs full-text search across many objects. Neither supports arbitrary joins or SELECT *.

Where you run queries

  • Apex: inline in square brackets, [SELECT … ], or dynamically with Database.query.
  • Developer Console → Query Editor (tick "Use Tooling API" for metadata like ApexClass).
  • CLI: sf data query --query "SELECT Id, Name FROM Account LIMIT 5" (add --result-format csv or --bulk).
  • REST API: GET /services/data/v64.0/query?q=SELECT+Id+FROM+Account.
  • VS Code's SOQL Builder, Workbench and other tools.

Relationship queries

Child to parent (dot notation)

Up to 5 levels up (A.B.C.D.E.Field), and up to 55 child-to-parent relationships in one query.

Parent to children (subquery)

Use the child relationship name (plural: Contacts, Opportunities, Cases, Invoices__r). Up to 20 subqueries per query; nesting up to 5 levels deep in recent API versions.

Semi-joins and anti-joins

Aggregates

Aggregate queries still count every row they scan toward the 50,000-row limit, and return at most 2,000 groups.

SOQL in Apex

Dynamic SOQL

SOQL injection is the most common security review failure. Never concatenate raw user input into a query string. Use binds; whitelist object and field names.
