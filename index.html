How Salesforce fits together

Salesforce is a hosted database with an application server, a security model, an automation engine and a UI framework layered on top. All of it is configured through metadata, which is why "clicks" (Setup screens) and "code" (Apex, LWC) can build the same things.

  UI --> SEC
  API --> SEC
  SEC --> AUTO
  AUTO --> DATA

Every request, whether from a person clicking Save or an integration calling the API, goes through the same security checks and the same automation before it reaches the database. That shared path is why a trigger written for the UI also runs for a data load of 50,000 records, and why governor limits matter so much.
