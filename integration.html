APIs & callouts

Inbound, other systems call Salesforce's APIs. Outbound, Salesforce calls other systems (callouts) or publishes events they subscribe to (Platform Events & CDC).

Authentication for inbound calls

External systems authenticate with OAuth 2.0 against an app definition in Salesforce: an External Client App (the current model) or a Connected App (older, still widespread). The app holds the consumer key/secret, allowed flows, scopes, and policies (which users, IP relaxation, token lifetime).

FlowUse when
Client CredentialsServer-to-server; the app runs as a designated "run as" integration user. Simplest for back-end jobs.
JWT BearerServer-to-server with a certificate; no secret sent. Common in CI (sf org login jwt).
Web Server (Authorization Code + PKCE)An app where a real user logs in and consents.
Refresh tokenKeep access without re-login after an authorization-code flow.
Username-passwordLegacy; avoid (blocked by default in new orgs).
Integration users: give each integration its own user on the free Salesforce Integration licence (API-only), with a permission set granting only what it needs. You can then see, limit and revoke each integration separately.

REST API

Base URL: https://<my-domain>.my.salesforce.com/services/data/vXX.X/. Send Authorization: Bearer <token>. JSON in and out.

Error responses

HTTP 400 for bad input, 401 for expired tokens (re-authenticate), 403 for permissions or API disabled, 404 for missing records, 503/REQUEST_LIMIT_EXCEEDED when the org is out of API calls.

Bulk API 2.0

For large volumes: upload CSV, Salesforce processes it asynchronously in parallel batches, you download success and failure files.

The CLI wraps this: sf data upsert bulk --sobject Account --file accounts.csv --external-id ERP_Id__c --wait 10 and sf data export bulk --query "…" --output-file out.csv --wait 10.

Apex REST services

Expose your own endpoint at /services/apexrest/… when the standard API isn't the right shape.

Test it by setting RestContext.request and RestContext.response in a test method, then calling the static method.

Outbound callouts

Named and External Credentials

  1. External Credential: the authentication protocol (OAuth 2.0 client credentials, JWT, custom headers / API key, AWS Signature v4) and its principals (the actual secrets, per-user or shared).
  2. Named Credential: the endpoint URL plus a reference to the External Credential. Code calls callout:Name/path.
  3. Grant users (including the integration or Automated Process user) access to the External Credential principal via a permission set.

No secrets or URLs in code, nothing to change in code between sandbox and production, and no Remote Site Settings needed.

Callout rules

  • No callouts after uncommitted DML in the same transaction (You have uncommitted work pending). Call out first, or move the callout to a Queueable / @future(callout=true) / async flow path.
  • No synchronous callouts from triggers. Enqueue async work from the trigger instead.
  • Up to 100 callouts per transaction and 120 s total; responses up to 6 MB sync / 12 MB async (heap).
  • Continuations let LWC/Visualforce controllers make long-running callouts without holding a server thread.
  • From Flow, use HTTP Callout actions or External Services (register an OpenAPI spec; operations become Flow actions).

Other integration tools

GraphQL API

POST /services/data/vXX.X/graphql — fetch exactly the fields and related records a client needs in one query. Also available to LWC as a wire adapter.

SOAP API

Older, WSDL-based (Enterprise and Partner WSDLs). Still used by some middleware and Data Loader.

Metadata & Tooling APIs

Deploy and inspect metadata; used by the CLI and IDEs.

Outbound Messages

Legacy SOAP notifications from workflow rules. Prefer platform events or flows with HTTP callouts.

Salesforce Connect

External Objects backed by OData 2.0/4.0, cross-org, or custom Apex adapters. Queried live; count against callout limits.

Heroku / AWS / MuleSoft connectors

Common for heavy processing outside Salesforce.
