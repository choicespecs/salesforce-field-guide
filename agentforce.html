Agentforce & Data 360

Agentforce is Salesforce's platform for AI agents that answer questions and take actions on your data. Data 360 (formerly Data Cloud) unifies data from many systems so agents, analytics and marketing can use it. Both build on the core platform you already know: flows, Apex and permissions.

This area changes fastest. Product names, limits and setup screens shift every release. Treat this page as a map of concepts and check current Salesforce Help for specifics.

Agent

A configured assistant with a role, a channel (internal employee agent, customer-facing service agent, etc.) and a set of topics. It runs as an agent user whose permissions limit what it can see and do.

Topic

A job the agent can do ("Check order status", "Reschedule appointment"), with a classification description, scope and natural-language instructions.

Action

Something the agent can call: an autolaunched Flow, an invocable Apex method, a prompt template, an API (via External Services or MuleSoft), or a standard action. The action's description tells the reasoning engine when to use it and what inputs mean.

Reasoning engine

Plans which topic and actions to use, asks for missing inputs, calls actions and composes the answer.

Agentforce Builder

Setup → Agentforce Agents. Configure topics and actions, test conversations, and see the reasoning plan for each turn.

Building actions

Agent actions are mostly things you already know how to build. Good descriptions matter as much as the code.

  • Least privilege: the agent user's permission sets decide what actions can touch. Use WITH USER_MODE and user-mode DML in actions.
  • Keep actions narrow: "Get order status" is better than "Run any query".
  • Confirmations: mark actions that change data as requiring user confirmation.
  • Outputs can be shown to the user directly or used by the reasoning engine to compose a reply.

Prompt templates

Prompt Builder (Setup → Prompt Builder) creates reusable prompts grounded in Salesforce data. Template types include Sales Email, Field Generation (fills a field on a record page), Record Summary and Flex (any inputs). Templates merge record fields, related records, flow outputs, Apex outputs and Data 360 data into the prompt.

Call a prompt template from Flow (as an action), from Apex (ConnectApi.EinsteinLLM.generateMessagesForPromptTemplate), from an LWC via Apex, or as an agent action.

Einstein Trust Layer

  • Secure data retrieval and grounding respect the running user's permissions.
  • Data masking replaces PII before the prompt leaves Salesforce, and restores it in the response.
  • Zero data retention agreements with model providers.
  • Toxicity scoring and audit trail (stored in Data 360) for prompts and responses.

Testing and monitoring agents

  • Use the Builder's conversation preview to see which topic and actions were chosen and why.
  • Testing Center runs batches of test utterances with expected topics, actions and responses — regression tests for agents.
  • Monitor production usage, escalations and feedback with Agentforce analytics; review audit data for quality and safety.
  • Agents consume usage-based credits — know your org's pricing model before scaling up.

Data 360 (Data Cloud)

Data 360 ingests data from Salesforce orgs and external systems, harmonises it into a common model, resolves identities into unified profiles, and makes the result available to segments, analytics, agents and apps. It can also zero-copy federate with warehouses like Snowflake, Databricks, BigQuery and Redshift instead of copying data.

Data stream

A connection that ingests data from a source on a schedule or in real time.

Data lake object (DLO)

The raw ingested data.

Data model object (DMO)

A harmonised entity in the Customer 360 data model (Individual, Contact Point Email, Sales Order…). DLO fields are mapped to DMO fields.

Identity resolution

Match rules (exact email, fuzzy name + address…) and reconciliation rules that merge records from many sources into a unified individual.

Calculated insight

A metric defined in SQL over DMOs, e.g. lifetime value or orders in the last 90 days.

Segment

A filtered audience of unified profiles, e.g. "customers with LTV > 5,000 who haven't ordered in 6 months".

Activation

Publishing a segment to a target: Marketing Cloud, ad platforms, an org, a file.

Data graph

A pre-joined, denormalised view of a profile and related data for fast lookups by agents and apps.

Data actions & triggered flows

React to changes in Data 360 by publishing events or starting flows in an org.

From Apex you can query Data 360 with ConnectApi.CdpQuery (SQL); from the org UI, Data 360 related lists and copy fields bring unified data onto CRM records.
