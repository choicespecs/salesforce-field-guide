Which one do I pick?

The design questions that come up every week, answered as tables. Each links to the chapter with the details.

Flow or Apex?

SituationPickWhy
Set fields on the record being savedBefore-save FlowFast, no DML, admin-maintainable
Create/update related records with straightforward logicAfter-save FlowVisible to admins; bulkified automatically
Guided UI for usersScreen Flow (embed LWCs where needed)Fast to build and change
Complex logic, many branches, reusable servicesApexEasier to test, review, refactor and version
Processing hundreds of thousands of recordsBatch ApexChunked with fresh limits per chunk
Callouts with complex request/response handlingApex (Queueable)Full control over HTTP, JSON, retries
Validation that needs other recordsApex trigger or Flow with Custom ErrorValidation rules can't query
Flow needs one thing it can't doFlow + invocable Apex actionKeep the process in Flow, the hard part in code
The object already has heavy Apex triggersApexOne tool per object keeps the order of execution understandable

Details: Flow, Triggers.

Lookup or master-detail?

NeedPick
Child can't exist without the parent; delete togetherMaster-detail
Roll-up summary fieldsMaster-detail (or a roll-up via Flow/Apex on a lookup)
Child needs its own owner and sharingLookup
Relationship is optionalLookup
Child is a standard objectLookup (standard objects can't be details)
Many-to-manyJunction object with two master-details
Parent has huge numbers of children with frequent updatesConsider lookup — master-detail locks the parent during child saves and roll-up recalculation
