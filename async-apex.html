Asynchronous Apex

Async Apex runs later, in its own transaction, with higher limits (200 SOQL queries, 60 s CPU, 12 MB heap). Use it for callouts after DML, slow work you don't want users to wait for, and processing large volumes.

Queueable

  • Delay: System.enqueueJob(job, 5) starts it after 5 minutes (0–10).
  • Check status: [SELECT Status, NumberOfErrors, ExtendedStatus FROM AsyncApexJob WHERE Id = :jobId].
  • Guard chaining in tests: only one chained job runs; check Test.isRunningTest() or use AsyncOptions to cap depth.
  • Prefer Queueable over @future for anything new.

@future

Future methods can't be called from another future or batch context, can't be chained, and give no job ID. They're also a classic way to avoid MIXED_DML_OPERATION (update a User in a future method).

Batch Apex

  • Each execute call is its own transaction with fresh limits. A failure in one chunk doesn't roll back the others.
  • Scope size: 1–2,000 (default 200). Use smaller scopes when each record makes callouts or heavy queries.
  • Iterable start: return an Iterable<SObject> (or any type) instead of a QueryLocator for non-SOQL sources; limited to 50,000 items.
  • Callouts: implement Database.AllowsCallouts; up to 100 callouts per execute.
  • Abort: System.abortJob(jobId) or Setup → Apex Jobs.

Schedulable

Cron expressions

Format: Seconds Minutes Hours Day_of_month Month Day_of_week [Year]. Use ? in one of day-of-month or day-of-week.

ExpressionRuns
0 0 2 * * ?Every day at 02:00
0 30 8 ? * MON-FRIWeekdays at 08:30
0 0 0 1 * ?Midnight on the 1st of every month
0 0 18 L * ?18:00 on the last day of every month
0 0 9 ? * 2#109:00 on the first Monday of every month
0 0 * * * ?Every hour, on the hour
Scheduled classes are locked. While a class is scheduled, you can't deploy changes to it (or classes it references) unless "Allow deployments of components when corresponding Apex jobs are pending or in progress" is enabled in Deployment Settings. Keep the Schedulable thin and put logic in other classes.

Monitoring

In Setup: Apex Jobs, Scheduled Jobs, Apex Flex Queue (reorder waiting batches). The org-wide daily async limit is the greater of 250,000 or 200 × user licences.

Other async options

  • Platform events published from Apex and handled by a trigger or flow run in a separate transaction as the Automated Process user — a decoupled alternative to Queueable (Events).
  • Asynchronous paths in record-triggered flows.
  • Apex Cursors (Database.getCursor) let queueables page through very large query results across chained jobs.
